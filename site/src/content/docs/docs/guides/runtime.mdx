At run time, `TypedDataFrame` and `TypedLazyFrame` are ordinary `pl.DataFrame` and `pl.LazyFrame` objects. A typed frame costs nothing, and the checker never looks at the data. So the type of a frame that comes from outside the program, such as a file, is only as good as the data in it. For such a frame, bind it to its schema once, at the point where it enters the program.

## Three functions

Each function takes a frame and a frame type, and returns the same frame with that type. For mypy, each call works like `typing.cast`: the result has the frame type. At run time, the three functions differ:

<Example name="runtime_check" />

| Function | At run time |
| -- | -- |
| `check_schema(df, Frame)` | Checks that the frame has exactly the declared columns, with the declared data types. It casts nothing, and it keeps the order of the columns. |
| `force_schema(df, Frame)` | Keeps only the declared columns, in their declared order, and casts each one to its declared data type. With `strict=False`, a value that Polars cannot cast becomes null. |
| `assume_schema(df, Frame)` | Checks nothing. |

`check_schema` raises an error if a declared column is missing, if a column has a different data type, or if the frame has a column that the schema does not declare. A column declared `Unchecked` has to be present, but its data type is not checked.

## A closed frame type

Each function needs a closed frame type: a schema class, and no remainder. An open frame type is an error, because its undeclared columns have no data type that the function can check or cast to:

A frame type with no schema class, such as `TypedDataFrame[Rest]`, gives the same error.

## Read the schema at run time

`.schema` on a typed frame returns the usual Polars `Schema`. The declarations are ordinary values at run time too, so you can inspect `column("price", pl.Float64)` in a running program.
