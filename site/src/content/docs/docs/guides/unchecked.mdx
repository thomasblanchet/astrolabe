Some Polars methods run a Python function on the data, such as `map_elements`. The checker cannot look inside a Python function, so it cannot know the data type that the function returns. It still knows the name of the result, though, and the rest of the frame.

## Unchecked keeps the name

`Unchecked` is the data type of a column whose name the checker knows, but whose data type it does not know:

<Example name="unchecked_map" />

Every later operation accepts an `Unchecked` column, so one Python function does not turn off the other checks. The other columns keep their data types, and reading a column that does not exist is still an error.

These calls give `Unchecked`: `map_elements`, `map_batches`, `pl.map_batches`, `pl.map_groups`, `pl.fold`, `pl.reduce`, `pl.cum_fold` and `pl.cum_reduce` without `return_dtype=`, `rolling_map`, and the `map_columns` of a frame.

## State the data type

`return_dtype=` states the data type that the Python function returns. The checker then gives the column that data type:

## Make it an error

At the level `stated` or stricter, a call without its `return_dtype=` is an error, and a note under the error names the setting that lets it pass. See [Make the checker stricter](../../tutorial/strictness/) and [Configuration](../../reference/configuration/).

A `Columns` class can also declare a column as `Unchecked`, for a column whose data type you do not want to fix. `check_schema` then checks that the column is present, but not its data type.
