An expression, such as `pl.col("price") * 2`, has no data type of its own: its data type depends on the frame that it runs on. So the checker gives each expression a type that holds its code. When the expression reaches a frame, the checker reads that code, and it works out the resulting column from the data types of that frame, with the typing rules of Polars.

## The checker works out each result

<Example name="expr_types" />

- `pl.col("price") * 2` keeps the name `price`. Its data type is `Float64`, because `price` is a `Float64`.
- `str.len_chars()` counts the characters of each string, and gives a `UInt32`.
- `when/then/otherwise` gives the common data type of its branches. Here one branch is `price`, a `Float64`, so the literal `0` in the other branch becomes a `Float64` too.

The same expression can give different data types on different frames, because the checker types it against each frame that it runs on.

## Aggregations

An aggregation, such as `sum()`, reduces a group of rows to one value. What that means for the result depends on the operation that runs the aggregation:

<Example name="expr_aggregations" />

- In `select`, the whole frame is one group, so the result is a frame with one row.
- In `with_columns`, the result must have one value for each row, so Polars repeats the sum on every row.
- In `agg`, each group gives one value, so the result has one row for each group.

A declaration can require an expression to work row by row, and the checker then rejects an aggregation in that place. See [Declare expression types](../expression-types/).

## Mistakes in an expression

If Polars refuses an expression at the data types of the frame, the checker reports it:

<Example name="expr_errors" />

- `round` needs a number, and `symbol` is a `String`.
- Polars cannot cast a `Datetime` to a `Boolean`.
- Polars cannot add a `Datetime` to a `String`.

An expression that Polars refuses at every data type is reported where you write it, before it reaches any frame.
