Astrolabe checks only the frames that it can type. A plain `pl.DataFrame`, such as a frame that a reader returns without a schema, stays plain, and the checker reports nothing about it. So adding the plugin to a large codebase does not flood the codebase with errors, and you can type the code one frame at a time.

## Steps

1. [Install and set up](../../start/install/) the plugin. At the default level, existing code gets few new errors, because most of its frames are still plain.
1. Type the frames where data enters the program. Give each reader a schema, or bind the frame to a schema with `check_schema`. See [Loading data](../loading/) and [Runtime checks](../runtime/).
1. Declare a `Columns` class for each frame that several functions share, and use it in their signatures.
1. Give an open frame type to each function that reads only a few columns of a larger frame. See [Open frames](../open-frames/).
1. Work through the errors. Each error has a code, and [Error codes](../../reference/error-codes/) gives its cause and its fix.
1. Once the code is clean at the default level, raise the level. See [Configuration](../../reference/configuration/).

## Silence one line

The usual controls of mypy still work. To silence one error on one line, add a comment with its code:

```python
df.select("venue")  # type: ignore[undeclared-column]
```

To turn off a code for the whole project, use the `disable_error_code` setting of mypy.

## Change the level of one operation

`allow_unproven_overrides` sets the level for a single operation, and it takes precedence over the global level. For example, the following makes the project stricter, but still accepts `map_elements` without `return_dtype=`:

```toml title="pyproject.toml"
[tool.astrolabe]
allow_unproven = "stated"

[tool.astrolabe.allow_unproven_overrides]
map_elements = "omitted"
```
