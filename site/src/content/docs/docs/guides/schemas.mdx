A schema describes the columns of a frame: the name of each column, and its data type. The checker uses the schema to know which columns a frame has at each step, so the schema is the first thing to declare. You declare it once, and you use it in the type of any frame that has those columns.

A schema has no order. Two frames with the same columns in a different order have the same schema.

## Declare a schema with a class

The usual way to declare a schema is a class that inherits from `Columns`. Each field of the class is a column, and the type of the field is the data type of the column, such as `pl.String` or `pl.Float64`. `Columns` itself declares no column. A class that inherits from another schema class gets all of its columns, and can add more:

<Example name="schemas_class" />

Here `Blotter` has the three columns of `Trades`, plus `venue`. `TypedDataFrame[Blotter]` is a closed frame type: a frame of this type has exactly these four columns, and no others. To type a function that accepts frames with more columns, see [Open frames](../open-frames/).

Two special forms exist. `TypedDataFrame` with no argument names no columns, so the checker treats it as a plain `pl.DataFrame`, and does not track it. `TypedDataFrame[()]` is a frame with no columns at all.

## Declare a schema with a dict

A field of a class needs a name that is a valid Python identifier, and column names such as `2024` or `v1|a` are not. For such names, declare the schema with `columns()`. It takes a name for the schema, and a dict that maps each column name to its data type:

## Give the parameters of a data type

Some data types have parameters: the time unit of a `Datetime`, the precision and the scale of a `Decimal`, the categories of an `Enum`, the inner data type of a `List`. In Polars code, you write these as calls, such as `pl.Datetime("us")`. A field of a class is a type annotation, though, and a type annotation cannot contain a call. So Astrolabe gives each of these data types a marker: a type that carries the parameters as type arguments.

<Example name="schemas_parameters" />

The checker keeps the parameters as part of the data type. So a `Datetime` in microseconds is a different data type from a `Datetime` in milliseconds. [Data types](../../reference/data-types/) lists every marker.

## Keep a data type in a variable

In Polars code, a data type with parameters is often stored in a variable, so that it is written only once. The declarations of Astrolabe read such variables:

<Example name="schemas_names" />

Every declaration that takes a data type as an argument reads the variable, with its parameters: `columns(...)`, `column(...)` and `other_columns(all_of=...)`. A variable that refers to another variable works too.

A field of a `Columns` class is different, because it is a type annotation, and mypy does not accept a variable in a type annotation. In a `Columns` class, write a type alias of the marker instead: `Stamped = Datetime[Literal["us"], None]` defines the alias, and `time: Stamped` declares the field.

## Write a generic schema

A schema can take a data type as a parameter, like a generic class, and each use of the schema then states that data type. One function can then accept frames whose `value` column has any data type, and return a frame with the same data type:

## Rules of a schema

A Polars column is never optional: a frame either has the column or does not. And the declared columns of a frame are its complete list of declared columns. So a `Columns` class follows two rules:

- Every field has a Polars data type, or a marker of one.
- The class does not use `total=False`, `closed=False`, `Required[...]` or `NotRequired[...]`.
