A pipeline starts by reading data. When the reader knows the schema of the data, the checker knows it too, and it can check every step that follows.

## Read a file with a schema

`pl.read_csv` takes a `schema=` argument, a dict that maps each column name to its data type. It is the usual way to tell Polars what a CSV file contains. The checker reads that dict as well, so the frame that `pl.read_csv` returns is typed from the first line:

<Example name="tut_load_schema" />

Nothing in this code comes from Astrolabe: it is plain Polars. Still, `reveal_type` shows that `trades` is a `TypedDataFrame` with three columns, and every later step on `trades` is checked against those columns.

## Without a schema, the frame is plain

When a reader gets no schema, Polars infers the data types from the file at run time. The checker runs before that, so it cannot know the columns. The result is a plain `pl.DataFrame`, which the checker does not track:

<Example name="tut_load_plain" />

Here the typo `prcie` goes unnoticed, because the checker does not know which columns `raw` has. So pass a schema to each reader. If a frame comes from a source that gives no schema, check it at run time with `check_schema`, as the chapter [Check the data at run time](../runtime/) shows.

:::note
Write the schema as a dict literal inside the call. The checker reads a dict that is written in the call, but it does not follow a dict that is stored in a variable.
:::
