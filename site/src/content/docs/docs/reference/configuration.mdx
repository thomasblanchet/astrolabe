Every setting lives under `[tool.astrolabe]` in `pyproject.toml`. `astrolabe init` writes each one at its default, with a comment.

| Setting | Default | Effect |
| -- | -- | -- |
| `allow_unproven` | `"omitted"` | The level: which results the checker accepts without a proof. |
| `allow_unproven_overrides` | none | A level for one operation, which wins over the global level. |
| `report_checker_gaps` | `false` | When true, the checker reports each checker gap at every level. |
| `disallow_vertical_concat` | `false` | When true, `pl.concat(how="vertical")` is an error. |
| `elevate_untyped_select` | `true` | When true, `.select()` on a plain frame gives a typed frame with each requested name. |
| `disallow_implicit_inferred_fallback` | `false` | When true, an inferred return type that falls back to the plain type is an error. |
| `disallow_implicit_inferred_fallback_overrides` | none | The same setting for one kind: `expr`, `dataframe` or `lazyframe`. |

The plugin warns about unknown keys and about values that it cannot read, and a setting with an unreadable value falls back to its default.

## allow_unproven

When the checker cannot prove a result, it does not guess. It records the result as unproven, with a reason, such as "a column name is not a literal string". Each reason belongs to one of the levels below, which run from the strictest, `never`, to the most lenient, `asserted`. The setting `allow_unproven` picks one level. The checker then accepts the reasons of that level and of every level above it in the table, without an error, and it reports the reasons of every level below it.

<LevelScale />

| Level | It accepts these reasons, and those of the levels above |
| -- | -- |
| `never` | Nothing. The checker also reports each checker gap. |
| `none` | Nothing on the scale. A checker gap passes, unless `report_checker_gaps = true`. |
| `stated` | A column name is not a literal string. An option of the call is not a literal. An expression is not typed. No schema gives the column types. The data type of a column decides whether a selector picks it, and no type declares it. A Python function decides the type. |
| `omitted` | A Python function decides the type, and no `return_dtype=` names it. No `dtype=` names the type of a `pl.Series`. A number variable has no fixed width. A data type is not written as a literal. |
| `possible` | The undeclared columns of the frame can hold the name, or not. The result depends on the undeclared columns that the caller passes. The caller can pass a join key of another form, which changes the join. |
| `asserted` | The undeclared columns of the caller do not prove the requirement. An argument is not typed, so its columns and types are unknown. The call is checked as declared, and the declared type is taken on trust. |

The default is `omitted`. At this level, the checker accepts the reasons of `stated` and `omitted`, and reports the reasons of `possible` and `asserted`.

A checker gap is a case that the plugin does not model. The cause is in the plugin, so there is nothing in your code to fix, and a gap passes at every level except `never`.

## allow_unproven_overrides

This sub-table sets the level for single operations, keyed by operation name:

```toml title="pyproject.toml"
[tool.astrolabe]
allow_unproven = "none"

[tool.astrolabe.allow_unproven_overrides]
map_elements = "omitted"
select = "possible"
```

The keys are `agg`, `concat`, `corr`, `drop`, `explode`, `fill_nan`, `fill_null`, `filter`, `fit`, `from_dict`, `from_dicts`, `from_numpy`, `from_records`, `get_column`, `group_by`, `group_by_dynamic`, `hstack`, `join`, `join_asof`, `join_where`, `map_batches`, `map_columns`, `map_elements`, `melt`, `pivot`, `read_csv`, `read_json`, `read_ndjson`, `read_parquet`, `remove`, `rename`, `rolling`, `rolling_map`, `scan_csv`, `scan_ndjson`, `scan_parquet`, `select`, `Series`, `unnest`, `unpivot`, `update`, `with_columns` and `with_row_index`.

The key `fit` covers each call to a function with a declared parameter. The key `get_column` also covers `df["a"]`.

## report_checker_gaps

When true, the checker reports every checker gap at every level. Use it to find where the plugin gives up for a reason that your code cannot fix.

## disallow_vertical_concat

A vertical concat stacks frames by column position. A type does not track column order, so the checker never types the result, and returns a plain frame. When true, every vertical concat, `"vertical"` and `"vertical_relaxed"` alike, is an error.

## elevate_untyped_select

When true, `.select()` on a plain frame returns a typed frame with the requested columns. Each column has the data type of its `.cast(...)`, or `Unchecked` if it has none. See [Loading data](../../guides/loading/).

## disallow_implicit_inferred_fallback

If one value that a function marks with `infer(...)` has a plain type, the whole return type of the function falls back to that plain type. By default this happens silently, and when true it is an error. The sub-table `[tool.astrolabe.disallow_implicit_inferred_fallback_overrides]` takes a boolean for each kind: `expr`, `dataframe` and `lazyframe`.
